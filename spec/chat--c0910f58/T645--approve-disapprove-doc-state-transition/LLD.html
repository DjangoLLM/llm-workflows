HTML Edge Override

A generated HTML design document may stamp its preferred state edge. The server parser owns this logic so the browser does not duplicate parsing rules.

CaseDecision
Complete meta stampUse the stamped current and next state names as the edge source.
Complete root data attributesUse the root pair when no conflicting meta stamp exists.
Both forms disagreeReject as malformed rather than guessing.
Partial or empty stampReject as malformed with a clear parser message.
No stampResolve from profile.state_edge_map using the story's live current state.

Backend API Contract

The endpoints live under the document registry boundary because that layer owns registered docs, task links, and safe file access.

Approve

POST /api/documents/{doc_id}/approve

Accepts project_id, task_id, optional profile, and optional note. Returns transitioned or noop_conflict with a clear message.

Disapprove

POST /api/documents/{doc_id}/disapprove

Accepts the same task context plus optional note. Persists the decision and returns recorded. It never calls the state update path.

Error / outcomeResponse behavior
Unknown doc404 with document_not_found.
Task mismatch409 with document_task_mismatch.
Scratch/no real task400 with task_document_required.
Missing edge409 naming the current state and profile source.
Unknown or renamed state409 naming the missing state and edge source.
Already advanced story200 noop_conflict; no update call.
Worktracker update failureSurface the failure as an error, never a silent false.

Backend Flows

The live story state is fetched before resolving and checked again against the resolved edge before any state update.

Approve

Load and validate documentReject unknown docs, scratch docs, and task mismatches.
Fetch live task stateCapture state_at_decision from current task details.
Resolve edgePrefer HTML override; otherwise use the profile map keyed by live state.
Resolve state IDsMatch exact state names against live project states and fail loudly on missing or duplicate names.
Guard and updateIf live state differs from expected current, record no-op. Otherwise call update_task_state.

Disapprove

Load and validate documentUse the registry row and selected task context; never parse the path segment.
Fetch live task stateRecord the current story state for future rework automation.
Persist decisionWrite disapproved, nullable note, and recorded outcome.
Return without transitionDo not call update_task_state or any status update wrapper.

Frontend Behavior

The action bar belongs to app chrome, not the sandboxed document. Results stay visible in the document tab because no-op conflicts are expected when an agent already advanced the story.

Visibility

Real task docs only

Hide controls without a selected project, without a selected real task, or for scratch docs. Disable controls while task details or a decision request is loading.

Approve result

Refresh after every outcome

On transition or no-op, show the backend message, refresh the module task list, and reload selected details if the same task is still selected.

Disapprove result

No status mutation

Show saved-decision feedback and leave Plane untouched. Optional note UI can wait unless an existing lightweight input pattern is already available.

Validation Plan

Tests focus on the guard, loud failures, persistence, and frontend refresh behavior.

Backend
  • Config loads old profile JSON with default edge map.
  • HTML parser accepts both stamp forms and rejects malformed stamps.
  • Approve works through profile-map and HTML-override paths.
  • Already-advanced stories return noop_conflict and skip update.
  • Unknown state names fail with the missing name and source.
  • Disapprove creates a nullable-note decision and never updates Plane.
Frontend
  • API client posts approve/disapprove payloads to local endpoints.
  • DocTab hides controls for scratch or no-task contexts.
  • Controls disable during requests.
  • Success and no-op messages trigger task and detail refreshes.
  • Errors show server messages without optimistic local state changes.
  • Profile-preserving flows keep state_edge_map.
