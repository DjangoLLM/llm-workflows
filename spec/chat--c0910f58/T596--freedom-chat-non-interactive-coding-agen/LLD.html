Implementation spec for core/cli_wrappers.py: a NonInteractivePolicy dataclass + a new ClaudeCLIWrapper, with Codex/Gemini made policy-aware. The coding-agent contract defaults to auto-approve + writes enabled + stream-json — the agent must be able to edit and run, since the point is to apply changes. Setting interactive=True reverts every wrapper to its native TUI.

1 · The policy object
A frozen, CLI-agnostic dataclass holding the two knobs + escalation. Lives beside OutputFormat in core/cli_wrappers.py.
@dataclass(frozen=True) NonInteractivePolicycore/cli_wrappers.py · new
+ auto_approveknob 1 bool = True Suppress approval/permission dialogues.
+ allow_writesdefault → True bool = True Edits + command exec permitted. Was read-only in HLD; flipped — a coding agent must apply changes.
+ output_formatknob 2 OutputFormat = STREAM_JSON Force text/stream-json; never a rich TUI.
+ interactiveescalation bool = False When True, wrappers drop non-interactive flags → native TUI.
★
Default = full coding posture; read-only and interactive are both reachable.
NonInteractivePolicy() with no args → auto-approve, writes on, stream-json. That is the contract freedom-chat uses to drive a coding agent. NonInteractivePolicy(allow_writes=False) gives a non-mutating "review/plan" run; interactive=True escalates to the TUI. Two convenience constants ship with it: CODING_AGENT_POLICY (the default) and READ_ONLY_POLICY.
2 · How the policy reaches a command — backward-compatible
execute() already forwards **kwargs to build_command(). We add one optional policy= kwarg. When absent, behavior is byte-identical to today (every existing test stays green). Explicit kwargs still win over policy-derived values.
precedence ruleapplied inside each build_command()
# Resolution order (highest wins):
#   1. explicit kwarg passed by caller   (e.g. sandbox="read-only")
#   2. value derived from `policy`        (if a policy was supplied)
#   3. the wrapper's hard-coded default   (today's behavior)

def build_command(self, prompt, output_format,

    if policy and not policy.interactive:

freedom-chat's call becomes: await wrapper.execute(prompt, policy=NonInteractivePolicy()). No CLI flag knowledge at the call site — the wrapper translates. This is the whole contract.

⚠
Claude's --output-format stream-json in print mode requires --verbose — the wrapper always pairs them automatically. For a coding agent that edits AND runs commands, bypassPermissions is the correct mode (acceptEdits would still block on bash). We standardize on the explicit --permission-mode form rather than the blunt --dangerously-skip-permissions alias.
4 · ClaudeCLIWrapper — the new class
Subclasses BaseCLIWrapper; inherits all of execute() (subprocess, streaming, stderr, timeout/kill, session tracking). Only three abstract methods + resume().
class ClaudeCLIWrapper(BaseCLIWrapper)core/cli_wrappers.py
class ClaudeCLIWrapper(BaseCLIWrapper):
    def __init__(self, api_key=None, model=None, working_dir=None, **kwargs):
        env = {}
        if api_key:
            env["ANTHROPIC_API_KEY"] = api_key   # else relies on logged-in claude
        super().__init__(working_dir=working_dir, env_vars=env, **kwargs)
        self.model = model

    def build_command(self, prompt, output_format,
                      policy=None, permission_mode=None,
                      model=None, resume_session=None,
                      allowed_tools=None, add_dir=None, **kwargs):
        interactive = bool(policy and policy.interactive)
        fmt = policy.output_format if (policy and not interactive) else output_format

        cmd = ["claude"]
        if not interactive:
            cmd.append("-p")                       # print / headless
            if fmt == OutputFormat.STREAM_JSON:
                cmd += ["--output-format", "stream-json", "--verbose"]
            elif fmt == OutputFormat.JSON:
                cmd += ["--output-format", "json"]

        mode = permission_mode or self._mode_from_policy(policy)
        if mode and not interactive:
            cmd += ["--permission-mode", mode]

        if (model or self.model):
            cmd += ["--model", model or self.model]
        if resume_session:
            cmd += ["--resume", resume_session]
        if allowed_tools:
            cmd += ["--allowedTools", ",".join(allowed_tools)]
        if add_dir:
            cmd += ["--add-dir", str(add_dir)]

        cmd.append(prompt)                       # positional prompt
        return cmd

    @staticmethod
    def _mode_from_policy(policy):
        if policy is None: return None
        if not policy.auto_approve: return "default"
        return "bypassPermissions" if policy.allow_writes else "plan"
5 · parse_event — Claude stream-json → unified CLIEvent
Claude emits one JSON object per line. We map its type onto the existing event vocabulary so BaseCLIWrapper._read_stream collects output and session id with no base-class change.
Claude lineKey fields→ CLIEvent.typeBase-class effect
{"type":"system","subtype":"init"} session_id, tools, model, cwd session.started Base captures session_id (already keys on it)
{"type":"assistant"} message.content[] (text blocks) content (text joined) Text appended to final_output
{"type":"user"} message.content[] tool_result blocks tool_result Surfaced to on_event; not in final text
{"type":"result"} result, usage, total_cost_usd, session_id, subtype done Final text + _extract_usage() source
→
assistant message content is a list of blocks; the parser concatenates text blocks into data["content"] so the base loop's "content" in event.data branch picks it up. _extract_usage() scans reversed events for the last done carrying usage (mirrors Codex/Gemini). session_id is read from both the init and result lines for resilience.
