Non-interactive coding-agent contract

#596 · chat–c0910f58 HLD
When freedom-chat drives a coding agent through freedom-agents core/cli_wrappers.py, the agent must run non-interactively: no approval/permission dialogues, and a plain/structured text stream instead of a rich TUI. Two independent knobs per CLI — approval and output — expressed once as a configurable policy, not hard-coded per call site.
The gap today
→
The knobs exist, but only as scattered per-CLI kwargs — and Claude has no wrapper.
Codex takes sandbox= + full_auto=; Gemini takes approval_mode=; each build_command invents its own argument names. A caller (freedom-chat) wanting "run non-interactively, text stream, no writes" must know each CLI's dialect. And there is no ClaudeCLIWrapper at all.
Core abstraction — one policy, translated per CLI
A frozen dataclass that captures the two knobs (+ escalation) once. Each wrapper's build_command reads it and emits its own flags.

★
Safe by default, escalation is opt-in.
Default policy = auto-approve dialogues but read-only (allow_writes=False) and stream-json output. Writes/exec require an explicit allow_writes=True. Setting interactive=True drops the non-interactive flags entirely so a human can drive the real TUI — the documented escalation path.

Escalation path — the contract stays optional
✓
interactive=True is a first-class mode, not a removed feature.
When a human needs to take the wheel (a destructive op the policy refuses, a debugging session), a policy with interactive=True tells every wrapper to omit its non-interactive flags and let the native TUI run. freedom-chat decides when to escalate; freedom-agents only honors the flag.

Open decisions — recommended defaults baked in
1 · Default permission level per agent?
Recommend: auto-approve dialogues ON, writes OFF (read-only) by default. Writes/exec is one explicit flag away. Matches "escalation is opt-in."
2 · Does this ticket own the chat-thread rendering of streamed events?
Recommend: No — freedom-agents stops at the normalized CLIEvent stream. Rendering is a freedom-chat seam (dashed edge), tracked separately under CODIN-584.
3 · Read-only Claude default — plan mode vs. restricted --allowedTools?
Recommend: --permission-mode plan as the read-only default (no edits/exec), since it is purpose-built for non-mutating runs.
