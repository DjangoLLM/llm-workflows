The state contract

The whole feature turns on one idea: a doc-chat session that TerminalHost owns an xterm for (it is in sessions) but that is never a tab (it is absent from byTaskId / activeByTask). A single new pointer, chatByTask, is how anything finds it.

terminalStore — new shape

chatByTaskRecord<bucket, SessionId> — the dedicated doc-chat session for each viewing bucket. The only index that references it.
openDocChat()Mints a temp session into sessions and sets chatByTask[bucket]. Deliberately does NOT push to byTaskId / activeByTask — so it is not a tab and never surfaces the ticket's run.
SessionMeta +isDocChat: boolean, docRelPath: string | null — carried into the WS init frame and the lifecycle label.
setReady (extend)The temp→server id swap already rekeys byTaskId + activeByTask; it must also rekey chatByTask so the pointer survives the swap. This is the single load-bearing edit.
attachPersisted (extend)A persisted row with scope==="docchat" routes to openDocChat (chatByTask), not openSession (tab) — restoring docRelPath from the row.

workspaceStore + init frame

overlayOpenPer-bucket boolean replacing the pill's chatOpen. True = the overlay is mounted over the active doc.
setOverlayOpen()Replaces setChatOpen. Closing only flips this flag — it never closes the session (background-and-reattach).
init.is_doc_chatNew boolean on the spawn-branch init frame (ws.ts → consumers _validate_init).
init.doc_rel_pathRepo-relative .html path of the active doc. Drives backend cwd + the seeded prompt.
AgentTerminalSession +doc_rel_path (nullable) persisted so a reload's reattach re-associates the overlay with its doc.

Invariants

  • Fresh always — summoning opens a new openDocChat run; it never adopts activeByTask[bucket] (the existing tab session). One overlay run per bucket; a second summon while one is live reveals the existing overlay run rather than forking.
  • Not a tab, ever — because it is absent from byTaskId, the tab strip's termIds.map never renders it; because scope==="docchat" is excluded from the running-count rollups, it never inflates a tree badge.
  • One xterm host — TerminalHost stays mounted exactly once. Only its wrapper's CSS moves between full-pane / overlay / hidden; the xterm DOM is never re-parented, so the session is never reset.
  • Close ≠ kill — closing the overlay sets overlayOpen=false only. The tmux run persists; reopening reattaches; a reload restores it via the docchat-scope branch.

One host, three presentations

The single TerminalHost mounts whichever session visibleId resolves to. Which session — and where the host box sits — is pure CSS + a store read. No second xterm, no DOM re-parent.
TERMINAL TAB ACTIVE
visibleId = activeByTask[bucket] — the ticket's run, full pane. Overlay closed.
DOC + OVERLAY OPEN
visibleId = chatByTask[bucket] — the doc-chat run, ~75% window, doc dimmed behind. This is the feature.
DOC, OVERLAY CLOSED
visibleId = null — host is invisible-but-measurable so fit() never sees a zero box. Doc reads clean.

The injected doc-chat prompt

One new builder in launcher.py, mirroring the existing design-dir block. Described by obligation; exact wording is implementation detail.
ROLEYou are editing one generated design document in place: <doc_rel_path>. The user will tell you what to change about it.
TARGETEdit the named .html directly. Your working directory is its design directory, so generated sibling docs are right here.
INPUTS / ACCESSThe generated HTML docs in this design directory, and the canonical template files seecode/templates/HLD.html · LLD.html as the design language to match. Both are readable from the repo checkout you run in.
STYLEKeep the doc on the shared token palette + interaction vocabulary of the exemplar — low-text, high-structure, clickable diagrams. The design-dir contract block is appended as for any run.
RELOADWhen you write the file, the #521 watcher fires a modify event and the doc tab reloads itself — no duplicate tab, no focus steal. You need do nothing extra.
FORBIDDENNo hard sandbox in this slice — scope is soft (cwd + this prompt). The agent can read neighbours; it simply should not, beyond the target doc and the named templates, unless asked.

Acceptance

The feature is done when, from a rendered generated document, you can summon a fresh, dedicated agent run via the picker; it opens a ~75% overlay that dims the doc and hosts that run in the single TerminalHost (in sessions, tracked by chatByTask, never a tab, never the ticket's existing run); the run is scoped to the doc's design dir with access to the generated docs and the canonical templates; you tell it what to change; it edits the .html in place; the #521 watcher reloads the tab live with no duplicate tab and no focus steal; closing the overlay backgrounds the run and reopening (or a page reload) reattaches it — and the chat-pill prototype is gone from the working tree.
