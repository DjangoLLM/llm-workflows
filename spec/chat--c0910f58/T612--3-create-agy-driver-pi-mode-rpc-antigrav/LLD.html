1 · What's genuinely new
The subprocess plumbing, streaming and event parsing already live in BaseCLIWrapper (T610). T612 adds only two things: the policy mapping and the registry wire.

One actionable knob. Pi in RPC mode has no approval/sandbox dialog — tool calls auto-execute — so a policy's auto_approve is inherently satisfied and is a genuine no-op for agy. The only knob pi exposes is a tool allowlist, so allow_writes is the one that maps to flags.

Backward-compatible. The policy= kwarg is optional. Absent a policy, build_command falls through to the legacy tools_enabled toggle and emits byte-identical args to the pre-T612 wrapper — no existing caller changes behavior.

★
Confirmed against pi --help.
pi exposes only --tools read,bash,edit,write (its default) or --no-tools. There is no interactive-approval surface in rpc mode. interactive=True is the escalation path: drop --mode rpc and hand pi the terminal as a native TUI.

4 · Registry wire — one factory
get_coding_agent("agy") resolves to a PiCLIWrapper pinned to google-antigravity; the caller's model is honored, defaulting to gemini-3-flash.
registry.py_make_agy
def _make_agy(working_dir: Path, model: Optional[str]) -> CodingAgent:
    return PiCLIWrapper(
        provider="google-antigravity",
        model=model or "gemini-3-flash",
        working_dir=working_dir,
    )

_REGISTRY = {"codex": _make_codex, "agy": _make_agy}
# Unknown name → UnknownCodingAgent(name, known=["agy","codex"])
