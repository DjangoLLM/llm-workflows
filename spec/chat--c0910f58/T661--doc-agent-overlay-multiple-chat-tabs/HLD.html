CODIN-661 HLD chat module

Multiple chat tabs in the document-agent overlay

Extend CODIN-625’s document-scoped agent overlay from one agent session per document to multiple persistent, independently running chat tabs. A user can open parallel coding-agent conversations over the same generated design document, switch among them without interrupting work, and return after closing the overlay or reloading the application.

Context uncovered

Existing feature

CODIN-625 is implemented in the plane-tui React/Django application, not in the supplied freedom-agents package. The latter is the required home for this ticket’s design artifacts.

Current frontend model

terminalStore.chatByDoc maps one docChatKey(taskId, relPath) to one terminal session. workspaceStore.overlayOpenByDoc controls whether each document’s overlay is visible.

Current presentation

TicketWorkspace renders a scrim and a roughly 75% overlay. One globally mounted TerminalHost resolves and attaches one visible xterm session, preserving terminals across ticket and tab changes.

Current summon behavior

DocTab opens AgentPicker for a fresh doc-chat. If a live session already exists for that document, it reveals the existing session instead of allowing another.

Persistence

Doc-chat runs are persisted with scope="docchat", task_id, and doc_rel_path. Restore routes them outside normal terminal tabs, but the current one-per-document map would collapse multiple restored runs.

Related work

CODIN-596 defines the non-interactive coding-agent stream contract. CODIN-606 extracted CLI drivers. CODIN-645 adds document approval controls to the same document-viewer surface and must remain compatible.

User experience

┌ Document agent overlay ─────────────────────────────────────────────── × ┐ │ [● codex 1] [◌ claude 1] [✓ agy 1] [+] │ ├───────────────────────────────────────────────────────────────────────────┤ │ │ │ active chat's existing xterm │ │ │ └───────────────────────────────────────────────────────────────────────────┘
  • The overlay’s header contains an ordered tab strip for the current document.
  • Each tab represents one persisted doc-chat run and displays agent name, a disambiguating ordinal, lifecycle state, and close control.
  • The + action opens the existing agent picker and always creates a new run for the active document.
  • Switching tabs changes only which existing xterm is mounted in the single terminal host; all other sessions continue running.
  • Closing the overlay backgrounds every chat for that document. Reopening restores the last active chat.
  • Closing a chat tab is distinct from closing the overlay and terminates that persisted agent run after confirmation.
  • If the active tab is closed, activate the nearest remaining tab. If none remain, dismiss the overlay and return to the document.

Decisions and proposed model

Scope remains per document

A chat belongs to the document it was summoned from. Switching documents shows that document’s own tab set; sessions do not migrate between docs.

No initial hard tab limit

The model supports an arbitrary number of chats. The strip must overflow horizontally without shrinking controls or the terminal below it.

One terminal host remains

Do not create an xterm host per visible tab. Continue using the existing global TerminalHost, which already owns one xterm entry per session and safely reattaches the selected entry.

Durable run identity drives restore

Multiple persisted rows may share task and document path. Their agent_run_id remains the unique identity; restore must append all live rows rather than deduplicate by document key.

  • web/frontend/src/panes/TerminalHost.tsx: resolve the active session for the active document.

  • web/frontend/src/modals/AgentPicker.tsx: doc-chat commit appends and activates rather than deduplicating.
  • Frontend store/component tests and restore tests; backend schema changes are not expected because persisted rows already have unique run ids and document paths.

Acceptance criteria

  1. A generated document’s overlay can host two or more simultaneous doc-chat sessions.
  2. The overlay header renders one tab per session and an add-chat control that launches the existing agent picker.
  3. Creating a chat never replaces or adopts an existing chat; the new session is appended and activated.
  4. Switching tabs shows the selected session’s existing terminal without restarting it, while non-selected sessions continue running.
  5. Chats are isolated by document and ticket/scratch bucket; switching documents shows only the active document’s chats.
  6. Closing the overlay does not terminate any chat and reopening restores the previously active live chat.
  7. Closing a chat tab terminates that run through the existing termination path, removes its indexes, and selects a neighboring tab; closing the last tab dismisses the overlay.
  8. Exited and errored sessions remain inspectable as tabs until explicitly closed and do not prevent launching another chat.
  9. Reloading the app restores every live persisted doc-chat run, without collapsing sessions that share the same document path or attaching the same run twice.
  10. Tab labels include agent identity, a stable disambiguator, lifecycle state accessible without relying only on color, and a close affordance.
  11. A long tab list remains usable through horizontal overflow, with add and overlay-close controls reachable.
  12. Normal ticket terminal tabs and running-agent tree counts remain unchanged; doc-chat sessions stay outside byTaskId/activeByTask and count rollups.
  13. Existing CODIN-625 behavior for doc live reload, overlay backgrounding, scratch docs, and per-document isolation continues to pass.
  14. Automated tests cover plural creation, active switching, temp-to-server id rekeying, termination, restore ordering/deduplication, per-document isolation, and overlay rendering.

Out of scope

  • Moving or sharing a chat between documents.
  • Combining multiple agents into one shared conversation transcript.
  • Changing coding-agent CLI stream contracts or provider drivers.
  • Displaying doc-chat runs as normal workspace terminal tabs or task-tree running counts.
  • Hard limits, quotas, or automatic eviction of old chat tabs.
  • Changes to CODIN-645 approval/disapproval semantics.
