1 · What moves, what wires, what waits
The big isolation decision is already settled in LAYERING.html (T596). This LLD refines the driver layer it points at — and narrows the active surface to the two drivers we drive today.

The whole monolith relocates. All 1209 lines of core/cli_wrappers.py move into coding-agent-drivers/src/coding_agents/, split across the modules below. Codex, Gemini, Claude and Pi wrappers all come along — nothing is left behind in core/.

Only two drivers get the new seam in v1. get_coding_agent() registers "codex" and "agy" (alias for the Pi/antigravity wrapper). Gemini and Claude classes ship in the package but are not registered yet — adding them later is one registry line each, no structural change.

from typing import Protocol, AsyncIterator, Optional
from pathlib import Path

class CodingAgent(Protocol):
    # Drive an external coding-agent CLI non-interactively.
    async def run(self, prompt: str,
                  policy: NonInteractivePolicy = CODING_AGENT_POLICY) -> CLIResponse: ...

    def stream(self, prompt: str,
               policy: NonInteractivePolicy = CODING_AGENT_POLICY) -> AsyncIterator[CLIEvent]: ...


def get_coding_agent(name: str, *, working_dir: Path,
                     model: Optional[str] = None) -> CodingAgent:
    # "codex" | "agy"  (gemini/claude raise UnknownCodingAgent until wired)
    try:
        factory = _REGISTRY[name]
    except KeyError:
        raise UnknownCodingAgent(name, known=sorted(_REGISTRY))
    return factory(working_dir=working_dir, model=model)
base.py — run() / stream() satisfy the protocoladded to BaseCLIWrapper
    async def run(self, prompt, policy=CODING_AGENT_POLICY) -> CLIResponse:
        return await self.execute(prompt, policy.output_format, policy=policy)

    async def stream(self, prompt, policy=CODING_AGENT_POLICY):
        queue: asyncio.Queue = asyncio.Queue()
        DONE = object()
        task = asyncio.create_task(
            self.execute(prompt, policy.output_format,
                         on_event=queue.put_nowait, policy=policy))
        task.add_done_callback(lambda _: queue.put_nowait(DONE))
        while True:
            ev = await queue.get()
            if ev is DONE: break
            yield ev
        self._last_response = await task   # re-raises timeout/launch errors
→
run() is a one-shot await → CLIResponse (maps to today's execute()). stream() bridges the existing on_event callback into an async for by pushing events through an asyncio.Queue; the final CLIResponse (and any raised error) surfaces when the backing task is awaited. No change to execute() itself.

5 · NonInteractivePolicy → CLI flags (codex · agy)
The policy is unchanged from T596 (auto-approve + writes + stream-json by default). This table is scoped to the two v1 drivers. Codex mapping already ships; agy is the new mapping work.
Policy statecodex (codex exec)agy (pi --mode rpc)
default
auto_approve + allow_writes		 --full-auto --sandbox workspace-write --json --tools — RPC auto-executes tool calls (no interactive prompt)
allow_writes = False
review / plan		 --full-auto --sandbox read-only --json --tools read — inspect only; no bash/edit/write
auto_approve = False --sandbox read-only (no --full-auto) no-op — rpc mode has no approval dialog to suppress
output_format --json for JSON / STREAM_JSON always JSON event stream (message_update / agent_end)

✓
Confirmed against pi --help — pi has no approval/sandbox flag.
pi exposes only a tool allowlist: --tools read,bash,edit,write (default) or --no-tools. There is no interactive-approval surface in rpc/non-interactive mode — tool calls auto-execute — so auto_approve is a genuine no-op for agy. The actionable knob is allow_writes: writes-on → the full allowlist, writes-off → --tools read (inspect only). A bare wrapper with no policy keeps its legacy --tools flag untouched.
⚠
Auto-approve suppresses the prompt — it does not make the action safe. Containment is the caller's job.
The default policy answers every approval dialog with “yes”, so the CLI's own prompt is no longer the safety net. The drivers therefore pick the most-contained posture that still permits writes rather than the hottest one: codex defaults to --sandbox workspace-write (sandbox stays ON), not danger-full-access — that is opt-in only. Even so, a bypassed agent that edits files and runs commands assumes the caller provides the outer guardrail: a git worktree (or container) per run, read-only mounts outside working_dir, and a network deny-list where the run is untrusted. This is a documented caller contract, not something the driver enforces.
✓
Driving agy through pi's RPC mode is the deliberate answer to antigravity's immature headless story.
Antigravity (agy) has the weakest non-interactive surface of the four CLIs — its community workarounds are node-pty/ConPTY screen-scrapers (brittle Approach B). Registering "agy" as the PiCLIWrapper (pi --mode rpc) sidesteps that entirely: pi gives a clean JSON event stream and a tool allowlist with no TTY prompt to scrape. We get the antigravity model without owning a PTY automation layer.

async def _stream_coding_agent(prompt, placeholder, *, working_dir):
    agent = get_coding_agent("agy", working_dir=working_dir)
    async for ev in agent.stream(prompt, CODING_AGENT_POLICY):
        if ev.type == "content":
            placeholder.content += ev.data.get("content", "")
            _debounced_save(placeholder)
        elif ev.type == "done":
            placeholder.mark_agent_success()
→
Two postures, one contract. A caller that wants a live thread uses stream() and writes deltas into the placeholder; a caller that only needs the answer uses run() and writes once. The actual chat wiring is its own ticket (rendering owned by CODIN-584) — T606 only guarantees the event vocabulary and the seam shape are stable.
↷
Deferred to T596: programmatic park-and-escalate, not just the binary interactive switch.
Today the only escalation is policy.interactive=True — drop the headless flags and hand the whole run to the native TUI (all-or-nothing, no chat seam). The richer design is to route each individual decision to a handler the caller owns — Claude Code's canUseTool / permission-prompt MCP, Codex's granular approval policy — and normalize a blocked decision onto one new event: CLIEvent(type="input_required", data={prompt, options, risk}). Chat would render that as a prompt against the GENERATING placeholder, suspend the run, and resume on the human's answer — a job that parks instead of blocking forever. This reframes NonInteractivePolicy (policy → auto-resolve → escalate) and extends the event vocabulary, so it is built under T596 (the chat seam), not in this isolation ticket. T606 only keeps the event/seam shape stable enough to add input_required later without a breaking change.

8 · Edge cases & decisions
CaseHandling
Backpressure on a slow consumerasyncio.Queue is unbounded; events buffer in memory. Acceptable for short coding runs. If a run floods, bound the queue later — out of scope now.
stream() error mid-runThe backing task captures the exception; it re-raises at await task after the loop drains. Caller's async for sees the events received so far, then the raise.
agy: policy ignored todayPiCLIWrapper.build_command gains a policy= kwarg; absent a policy, behavior is byte-identical (legacy). allow_writes → --tools/--no-tools.
Unknown name vs deferred driverget_coding_agent("gemini") raises UnknownCodingAgent("gemini", known=["agy","codex"]) — same path as a typo, until gemini is registered.
No-policy legacy callersThe two existing test suites import the same symbols from coding_agents instead of agents.core.cli_wrappers; behavior unchanged.
interactive=TrueHonored per-driver (codex drops exec; agy drops --mode rpc). The caller decides escalation; the driver only obeys the flag.
