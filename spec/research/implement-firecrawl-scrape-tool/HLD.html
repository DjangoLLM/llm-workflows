High-level design for the Firecrawl-backed scrape_url tool. One toolset, one HTTP call, loud failures.
STATE · TODO PHASE · HLD PARENT · §6.3 typed-search-and-scrape SIBLINGS · #380 · #390 · #392
Ship
A ToolSet subclass that fetches a URL via Firecrawl /v1/scrape.
Contract
ScrapeUrlInput → ScrapeUrlOutput. No coercion, no retries, no cache.
Failure stance
Anything off-script raises ToolExecutionError with full context.

05
Failure surface
CONFIG
Missing env var
"config: FIRECRAWL_URL missing" or "FIRECRAWL_API_KEY missing" — raised in __init__, before any request.
HTTP · non-2xx
Provider returned an error status
provider_status = response.status_code · provider_body = response.text[:2KB]
TRANSPORT
Timeout / DNS / refused
httpx.RequestError caught and re-raised with the underlying exception class in the message.
BODY · shape
Not an object · success:false
Provider succeeded HTTP-wise but signaled failure in the body, or the body isn't JSON.
BODY · missing keys
data · metadata · url · statusCode
Required path absent → named in the error message. No silent default.
PROPAGATES
ValidationError on output
Pydantic error from constructing ScrapeUrlOutput is treated as a contract violation — not caught.
Every ToolExecutionError carries tool_name="scrape_url" and input_snapshot={"url": …, "formats": […]}. No silent coercion — e.g. a string statusCode is not int-cast.
06
Acceptance
  1. firecrawl.py exists with FirecrawlScrapeToolSet(ToolSet) and class attr name = "scrape_url".
  2. __init__ reads both env vars; each absent/empty raises ToolExecutionError("config: <var> missing").
  3. One @tool method scrape_url issues the documented POST via httpx.Client.
  4. Successful response maps to ScrapeUrlOutput per the mapping table and og rule.
  5. Non-2xx · transport · malformed body · missing keys → ToolExecutionError with full context. Zero silent coercion.
  6. No registry side effects on import. scrape_url/__init__.py unchanged.
