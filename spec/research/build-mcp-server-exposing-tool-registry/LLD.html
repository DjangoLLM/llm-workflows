4 ToolSet & @tool decorator

ToolSet base

  • One required class attr: name: ClassVar[str]. Missing → TypeError at register time.
  • Base __init__ is a no-op. Subclasses raise in __init__ to fail config — registry does not catch.
  • No get_tools() on the instance. Method-walking lives in the registry.

@tool decorator

  • Keyword-only: input_model, output_model, mcp_safe=False, name=None.
  • Attaches __agent_tool__ metadata; otherwise returns function unchanged.
  • Method stays normally callable from in-process code (no registry indirection).

Validation timeline

WhenCheckFailure
Decorationinput/output are BaseModel subclassesTypeError
DecorationCallable is a functionTypeError
RegistrationBound method signature is (self, input)TypeError w/ tool+toolset names
Registrationinput annotation matches input_model (if present)TypeError (mismatch) / stderr warning (missing)

Method discovery: walks vars(cls) over MRO (excluding object, ToolSet), collects attrs with __agent_tool__. Inheritance supported but not tested in v1.

5 ToolRegistry — write/read split

Internal state

AttributeTypeHolds
_toolsetsdict[str, type[ToolSet]]Toolset class by name.
_toolset_metadict[str, _ToolsetMeta]module, expose_mcp, instance, tools (source order).
_toolsdict[str, Tool]Flat tool-name → descriptor.

register_toolset — atomic order

  1. Validate toolset_cls.name; reject duplicate toolset.
  2. Instantiate toolset_cls(). Exceptions propagate unchanged (config-time failures).
  3. Walk MRO, build Tool descriptors with bound_method = getattr(instance, attr_name). Empty toolset → hard error.
  4. MCP gate: if expose_mcp=True, every member must be mcp_safe=True — else ValueError with pinned message.
  5. Cross-toolset uniqueness: reject any tool name that collides with an existing registered tool.
  6. Commit _toolsets, _toolset_meta, _tools only after all validations pass — registry never half-populated.

Read surface

get_toolset(name) → class (not instance) toolset_names(modules?, exposed_only?) resolve_toolset(name) → tools in registration order get/run/names — flat tool surface

run accepts dict or BaseModel; pydantic ValidationError propagates.

6 MCP adapter

build_tool_adapter(tool) returns a function whose __signature__ mirrors the input model's fields exactly.

DecisionValue
Parameter kindAll keyword-only.
Defaultsf.default if not PydanticUndefined; else Parameter.empty (required).
AnnotationsPropagated from input_model.model_fields[n].annotation.
Return annotationdict. Body returns output.model_dump(mode="json").
__name__ / __qualname__Both set to tool.name.
__doc__Copied from bound_method.__doc__.
Error mapping (deliberately not caught):
  • pydantic.ValidationError from input → FastMCP tool-call error.
  • ToolExecutionError from method → FastMCP tool-call error, attributes preserved.
  • Any other Exception → MCP error, server stays up (FastMCP contract; asserted in tests).

7 MCP server build

  1. Look up toolset in registry.toolset_names(exposed_only=True). Missing/unexposed → SystemExit(2) with mcp.server.refused reason=not-registered|not-exposed.
  2. Lazily import fastmcp (not at module top). Import failure → SystemExit(3) reason=fastmcp-missing.
  3. For each tool in resolve_toolset, register build_tool_adapter(tool) via server.tool(...).
  4. Emit one stderr line: mcp.server.bound toolset=<name> tools=<sorted names>.
  5. Return the FastMCP instance. Transport is not started here.

No multi-toolset path. No port allocation. No supervisor.

8 Runner

run(toolset_name, *, transport="stdio", host="127.0.0.1", port=None, name=None, registry=default_registry)

TransportArgs usedBehavior
stdio (default)—server.run(transport="stdio")
httphost, port (required)HTTP transport on given host:port.
ssehost, port (required)SSE transport on given host:port.
Boot-gate invariant: this module is the only place a transport starts. It is imported only from the run_tools_mcp command — never from AppConfig.ready(), tools/__init__.py, or list_toolsets. Verified by test_boot_gate.py.

All boot logs go to stderr; stdout is reserved for the STDIO transport. Missing --port with http/sse → SystemExit(2) reason=port-required.

16 Risks & mitigations

RiskMitigation
fastmcp API drift between minor versions.Pin >=2,<3; bump in lockstep with freedom-plane-agent.
FastMCP strips exception attrs converting to MCP errors.Asserted by adapter tests; if it strips, adapter takes ownership of re-encoding — but only revisited if the test fails.
register_toolset instantiates eagerly in AppConfig.ready(); env-reading toolsets break test bootstrap.Fixtures have env-free __init__. Production toolsets accept: missing env = loud Django startup failure (by design).
_toolsets.py picked up by pytest.Leading underscore — python_files = test_*.py excludes it.
Coverage drop from mocked runner.Documented; not a blocker.

17 Out-of-scope guardrails

If these come up during implementation, stop and surface — do not expand scope:
  • Migrating PlaneToolset (separate ticket).
  • Cross-module toolsets / cross-app tool composition.
  • Auto-inferring input_model/output_model from method hints.
  • Multi-toolset-per-process supervisor or port allocation.
  • mcp_safe-only subset exposure within a partially-safe toolset (the invariant is all members mcp_safe=True).
