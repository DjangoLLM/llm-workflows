HLD: register(..., expose_mcp=…) for freedom-agents tools

Plane #396 · scope: freedom-agents substructure only · builds on #380 (tools registry)

1 · Goal

Make MCP exposure a flag on tool registration. After this lands, turning a registered tool into part of an MCP server is one keyword argument; no per-toolset boilerplate, no separate server files. 

# Before: write a bespoke FastMCP server per toolset (see plane_agent/mcp/)
# After:
default_registry.register(EchoTool(), expose_mcp="demo")
default_registry.register(SearchWebTool(), expose_mcp="research")
default_registry.register(ScrapeUrlTool(), expose_mcp="research")
# Boot Django -> two FastMCP servers come up: "demo" and "research".

2 · In / out of scope

  • In: the expose_mcp argument; the in-process server-supervisor that owns one FastMCP per group key; an adapter from the Tool Protocol to a FastMCP-compatible callable.
  • Out: any new tool implementations; migrating plane_agent/mcp/ (left alone); STDIO transport; auth; multi-agent fan-out; pi-side spawning.

3 · Architecture

Three pieces, all inside agents/tools/:

ComponentResponsibility
ToolRegistry.register(tool, *, expose_mcp=None) Stores tool. If expose_mcp is a string key, also enrolls tool into McpServerSupervisor under that key.
agents/tools/mcp/adapter.py Wraps a Tool (Protocol from #380) into a FastMCP-registerable callable: builds a signature from tool.input_model, calls tool.run(validated), dumps the output_model.
agents/tools/mcp/supervisor.py Lazy dict key → FastMCP. On first enroll for a key, constructs FastMCP(key); on Django boot, starts each in its own daemon thread on its configured port.

3.1 · Tool → FastMCP adapter

The Tool Protocol already gives us input_model and output_model (pydantic). FastMCP introspects callables for parameter names/types, so the adapter generates a function whose parameters mirror input_model fields and whose body does tool.run(input_model(**kwargs)). Structurally the same trick as _wrap_plane_tool, but driven by the schema instead of a method signature — cleaner because Tool has the schema explicitly.

3.2 · Supervisor lifecycle

  • AgentsConfig.ready() checks sys.argv: if and only if the management command is runserver, it calls McpServerSupervisor.start_all() after the existing catalog validations. Other commands (migrate, shell, test, run_temporal_worker) skip it entirely.
  • Ports are assigned in registration order starting at 8200: first enrolled group → 8200, next → 8201, and so on. The supervisor logs mcp.server.bound group=<key> port=<n> for each.
  • Each FastMCP server runs on its own daemon thread via fastmcp's HTTP transport.
  • No explicit stop: daemon threads die with the Django process. Acceptable for the in-process model.

4 · What changes in code

# agents/tools/registry.py
class ToolRegistry:
    def register(self, tool: Tool, *, expose_mcp: str | None = None) -> None:
        if tool.name in self._tools:
            raise ValueError(f"Tool '{tool.name}' is already registered.")
        self._tools[tool.name] = tool
        if expose_mcp:
            from agents.core.tools.mcp.supervisor import McpServerSupervisor
            McpServerSupervisor.enroll(group=expose_mcp, tool=tool)

# agents/apps.py  (additions only)
import sys

def ready(self):
    ...  # existing catalog registrations + validation
    if "runserver" in sys.argv:
        from agents.core.tools.mcp.supervisor import McpServerSupervisor
        McpServerSupervisor.start_all()

Nothing else touches existing files. plane_agent/mcp/ stays as-is. default_registry keeps current behavior when callers don't pass expose_mcp.

5 · Decisions taken

decided Server granularity: per group key. expose_mcp="research" aggregates tools sharing that key into one server. Multiple keys → multiple servers.
decided Lifecycle: in-process daemon threads inside the Django process.
decided Boot gating: servers only start when Django is launched via runserver. Detected by inspecting sys.argv inside AgentsConfig.ready(). migrate, shell, test, run_temporal_worker, etc. do not open ports.
decided Port allocation: auto-increment starting at 8200. First enrolled group gets 8200, next 8201, etc., in registration order. No config knob. A logger line prints group=<key> port=<n> at boot so the binding is discoverable.
decided fastmcp dependency: hard dependency in freedom-agents's pyproject.toml. No optional-extras dance.
decided Server name = group key. FastMCP(key). No separate name argument.
decided Existing code: plane_agent/mcp/ is not touched. This HLD only builds the freedom-agents substructure; no Plane migration in this story.
decided Flag location: argument on register(), not a field on the Tool Protocol. Keeps tool authoring independent of deployment shape.
decided Transport: HTTP. STDIO is explicitly out of scope.

6 · Decisions deferred

defer Name collisions across groups. Registry currently enforces global-unique tool names, so this can't bite us yet. Revisit if/when we want the same tool name to live in two groups; not part of #396.

7 · Out of scope (explicit, to prevent scope creep)

  • Migrating PlaneToolset to the registry — separate ticket, once the pattern is proven.
  • STDIO subprocess model for pi-spawned agents.
  • Auth, rate limiting, observability on the MCP servers — revisit when there's a real client beyond local dev.
  • A formal ToolSet base class — not needed for this story.
